# Синхронизация мест с Google Places

Скрипт `src/scripts/syncGooglePlaces.ts` подтягивает из Google Places API (New)
актуальные данные по каждому месту и обновляет их в MongoDB (коллекция `newplaces`):

| Поле в базе                   | Откуда из Google                          | Правило записи                                  |
| ----------------------------- | ----------------------------------------- | ----------------------------------------------- |
| `properties.openingHours`     | `regularOpeningHours.weekdayDescriptions` | если Google вернул часы и они отличаются        |
| `properties.phone`            | `internationalPhoneNumber`                | если Google вернул номер и он отличается        |
| `properties.website`          | `websiteUri`                              | если Google вернул сайт и он отличается         |
| `properties.businessStatus`   | `businessStatus`                          | если отличается (закрытые скрываются, см. ниже) |
| `properties.googleId`         | `id`                                      | если Google перевёл место на новый Place ID     |

Не трогает: `name`, `address`, `geometry.coordinates`, `description`, `image`,
`instagram`, `additionalInfo`, `neighborhood`. Ничего не удаляет.

Места без `properties.googleId` пропускаются.

## Find on Google: поиск Place ID для заявки на добавление места

`findGoogleIdsForSuggestion(id, token)` (GraphQL-резолвер, review-страница
админа) ищет до трёх Google Place ID по имени и адресу заявки — Text Search
(New) с `X-Goog-FieldMask: places.id`. Это SKU **Text Search Essentials IDs
Only**, он бесплатен без ограничения по количеству запросов, в отличие от
Place Details выше — запрашивать любое другое поле здесь нельзя, это увело бы
вызов на платный SKU. Использует тот же `GOOGLE_PLACES_API_KEY`.

Как только админ выбирает один из кандидатов и публикует заявку с этим Place
ID, следующий месячный прогон `syncGooglePlaces` подтянет для нового места
часы, телефон и сайт по этому ID — отдельного платного вызова при публикации
нет.

## Как запускать

Нужен `.env` с `MONGO_URI` и `GOOGLE_PLACES_API_KEY` (плюс остальные переменные,
которые требует `src/config/config.ts`). Скрипт пишет в ту базу, на которую указывает
`MONGO_URI`.

```bash
npm run build

# 1. Проверка на нескольких местах, без записи в базу
node dist/scripts/syncGooglePlaces.js --limit=5

# 2. Полный прогон без записи: печатает, что изменится
node dist/scripts/syncGooglePlaces.js

# 3. Запись в базу
node dist/scripts/syncGooglePlaces.js --apply

# Можно комбинировать: записать только первые 100 мест
node dist/scripts/syncGooglePlaces.js --apply --limit=100
```

Без сборки, прямо из TypeScript:

```bash
node --no-warnings --loader ts-node/esm src/scripts/syncGooglePlaces.ts --limit=5
```

| Флаг        | Что делает                                                              |
| ----------- | ----------------------------------------------------------------------- |
| (без флагов)| dry run: печатает изменения, в базу не пишет                            |
| `--apply`   | записывает изменения в базу                                             |
| `--limit=N` | обрабатывает только первые N мест (порядок по `_id`, стабильный)         |

**Важно: dry run тоже стоит денег.** Он делает те же запросы к Google, просто не пишет
результат. Не гоняйте полный dry run «на всякий случай», проверяйте на `--limit=5`.

### Как читать вывод

```
~ Caffeinery (68861721af72dc0dcf7c00ff)          <- место, которое изменится
  properties.phone: "+49 163 5880619"            <- новое значение

Would update 142 of 190 places                   <- с --apply: "Updated ..."

Not operational (hidden from listings):          <- закрытые по данным Google
  Bricks & Mortar (...): CLOSED_PERMANENTLY

Place ID not found:                              <- Google не знает этот Place ID (404)
  InPiazza Café (...)

Failed requests:                                 <- прочие ошибки API, место не обновлено
```

Что делать после прогона:

- **Place ID not found**: найти место в Google Maps вручную и обновить `googleId`,
  или удалить/скрыть место, если его больше нет. Скрипт такие места не трогает.
- **Failed requests**: обычно временная ошибка, достаточно перезапустить позже.
  Если `403`, проверьте ключ и billing (см. «Google Cloud»).

## Деньги и квоты: главное ограничение

Запрашиваемые поля (часы, телефон, сайт) относятся к SKU
**Places API Place Details Enterprise**:

- **1000 запросов в месяц бесплатно**, дальше **$20 за 1000** (цены проверены в
  консоли Google Cloud в сентябре 2026, могут измениться).
- Один запрос = одно место. Полный прогон = столько запросов, сколько мест с `googleId`
  (на сентябрь 2026 это 446).
- **Значит, полный прогон можно делать не чаще двух раз в месяц**, иначе платно.
  Безопасный ритм: раз в месяц.
- Счётчик обнуляется 1-го числа каждого месяца.
- Ответы с ошибкой `429` не тарифицируются.

Если месячный лимит почти выбран, считайте остаток и используйте `--limit`.
Точного счётчика в консоли нет (в Metrics только запросы в секунду), поэтому
расход надёжнее всего вести по логам прогонов.

Бюджет `coffeemap minimal budget` ($1/мес) только **присылает письма** при 50/90/100%,
он **не останавливает** расходы. Настоящий spend cap Google для Places не поддерживает.
Если нужен жёсткий потолок, ставьте дневную квоту на Place Details в
APIs & Services → Places API (New) → Quotas.

### Поминутный лимит (429)

У Google есть лимит запросов в минуту. Скрипт делает 3 запроса параллельно и
при `429` ждёт 15/30/45/60 секунд и повторяет (до 4 раз). Если места всё равно
попали в `Failed requests` с кодом 429, просто перезапустите позже.

## Закрытые места

Google отдаёт `businessStatus`: `OPERATIONAL`, `CLOSED_TEMPORARILY` или
`CLOSED_PERMANENTLY`. Скрипт сохраняет его в `properties.businessStatus`
(по умолчанию в схеме `OPERATIONAL`).

Места со статусом `CLOSED_TEMPORARILY` и `CLOSED_PERMANENTLY` **скрыты из всех списков**,
но остаются в базе. Фильтр лежит в `src/models/Place.ts`:

```ts
export const VISIBLE_PLACE_MATCH = {
  "properties.businessStatus": { $nin: ["CLOSED_TEMPORARILY", "CLOSED_PERMANENTLY"] },
};
```

Где применяется:

| Где                                                    | Эффект                              |
| ------------------------------------------------------ | ----------------------------------- |
| `allPlacesResolver` (`getPlacesWithStats`)             | список и `total`                    |
| `filteredPlacesResolver`                               | фильтры и `total`                   |
| `favoritePlacesResolver`                               | избранное пользователя              |
| `availableNeighborhoodsResolver`                       | список районов для фильтра          |
| `availableAdditionalInfoTagsResolver`                  | список тегов для фильтра            |

Где **намеренно не применяется**: страница места по id (`placeResolver`), история
отзывов пользователя (`userReviewActivityResolver`), лайки и оценки. Старые ссылки
и отзывы продолжают работать.

Статус обновляется в обе стороны: если временно закрытое место снова открылось,
следующий прогон с `--apply` поставит `OPERATIONAL`, и место вернётся в выдачу.
Между прогонами статус не меняется, автоматического запуска пока нет.

Вручную скрыть или вернуть место:

```js
db.newplaces.updateOne({ _id: ObjectId("...") }, { $set: { "properties.businessStatus": "CLOSED_PERMANENTLY" } })
db.newplaces.updateOne({ _id: ObjectId("...") }, { $set: { "properties.businessStatus": "OPERATIONAL" } })
```

Учтите: следующий прогон перезапишет ручной статус тем, что скажет Google.

**Если добавляете новый запрос, который отдаёт список мест, добавьте в него
`{ $match: VISIBLE_PLACE_MATCH }`**, иначе закрытые места снова появятся.

## Нюансы

### Кэш районов и тегов

Списки районов и тегов кэшируются в памяти сервера на 24 часа
(`src/utils/cache.ts`). После прогона с `--apply` работающий сервер покажет
новые районы/теги только после перезапуска или истечения кэша. Сами места
обновляются сразу, кэша у них нет.

### Формат часов работы

Google возвращает `Monday: 9:00 AM – 5:30 PM`. Скрипт приводит к формату, который
уже был в базе: `{ day: "Monday", hours: "9 AM to 5:30 PM" }`:

- `–` → ` to `;
- `:00` убирается (`9:00 AM` → `9 AM`);
- неразрывные пробелы (U+202F перед AM/PM, U+2009, U+00A0) → обычный пробел.

В старых данных перед AM/PM стоит U+202F, поэтому при сравнении пробелы в базе
тоже нормализуются. Без этого почти все места выглядели бы изменёнными.
Выходной день приходит как `Closed`, интервалы через запятую сохраняются как есть.

Часы запрашиваются на английском (`languageCode=en`), под него же рассчитан парсинг.

### Адрес и координаты

Не синхронизируются. В базе адрес хранится коротко (`Chausseestraße 52, 10115`),
а у Google полный (`..., 10115 Berlin, Germany`). Автозамена сломала бы единый формат.

### Условия Google (ToS)

По правилам Google Maps Platform бессрочно хранить можно только Place ID. Остальные
данные Places формально можно лишь кэшировать на ограниченный срок. Проект
сохраняет часы, телефон и сайт в базе. Это осознанный компромисс, но о нём
стоит помнить.

## Для разработчиков и AI-ассистентов

- Перед любым запуском без `--limit` посчитайте, сколько запросов уже потрачено в
  этом месяце. Каждый запрос тарифицируется, включая dry run.
- Для проверки изменений в логике используйте `--limit=5`, не полный прогон.
- Не запускайте `--apply` без явной просьбы владельца проекта: скрипт пишет в базу
  из `MONGO_URI`.
- Одноразовые скрипты, которые импортируют сервисы с кэшем (`src/utils/cache.ts`),
  не завершаются сами из-за `setInterval`. Заканчивайте их `process.exit(0)`.
